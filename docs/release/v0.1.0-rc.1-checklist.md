# v0.1.0-rc.1 无签名候选验收清单

本文件是长期维护的门禁模板和证据路由表，不复制某一次运行的易失 commit、run ID、文件大小或哈希。最终候选的动态事实记录在 PR #2 的 exact-head 验收证据中，产物字段记录在候选下载包内的 `BUILD-MANIFEST.json` 与 `SHA256SUMS.txt` 中。

## 状态词与门禁类型

- `SEE_PR_EVIDENCE`：从 PR #2 的最终 head 验收记录读取，不在本模板手填。
- `SEE_BUILD_MANIFEST`：从最终候选的构建清单及独立重算记录读取。
- `PENDING`：仅用于仍需人工执行的检查，不表示自动化门禁失败。
- `PASS` / `FAIL`：人工检查实际执行后的结论。
- `NOT_RUN`：该执行环境没有运行，不得解释为通过；可能仍是必须在另一个授权环境补齐的门禁。
- `AUTO_GATE`：转 Ready 前必须由 exact-head CI 或独立产物复核通过。
- `INSTALLED_GATE`：发布负责人对最终 commit 和实际 artifact 哈希对应的安装应用进行人工验收，转 Ready 前强制完成，不能被源码或 Fake 测试替代。
- `OUT_OF_SCOPE`：本 RC 明确不实施、不验收。

## Ready 判定

PR #2 只有在以下条件同时满足时才能从 Draft 转为 Ready：最终 PR head 的 `desktop-ci`、`macos-arm64-rc` 与 `rc-manifest` 全部通过；macOS built-sidecar、正常 packaged-app、Launch Services 启动和异常退出清理门禁全部通过；两项最终下载产物的大小与 SHA-256 经独立重算并与清单一致；使用用户自有 Key 的中文混合材料真实 GLM 语义、OCR/图片/扫描件验收通过；以下全部 `INSTALLED_GATE` 通过；安全检查无失败；review conversation 无未解决阻断项。

任一自动化门禁为失败、取消、跳过或证据仍未形成时，PR 必须保持 Draft。转换 Ready 仅表示候选已达到代码审查门槛，不授权合并、打 tag、发布 Release、签名或公证。

## 已知限制

- 候选不包含 macOS Developer ID 签名或公证。
- macOS 候选仅使用 ad-hoc 签名，并明确关闭 hardened runtime，以兼容内置的 PyInstaller sidecar；正式分发签名与公证仍不在本 RC 范围。
- Windows 安装包、多 Provider 用户配置、Word 报告和自动更新不在本 RC 范围；图片/扫描件真实模型验收在强制范围内。
- 当前桌面范围保留通用 R01—R20 目录/回归，但 `labor_materials_v1` 不执行工资/考勤对账或金额计算；工资合同条款观察仍保留。没有证据或仅部分成功不等于安全。
- 底层 OpenAI 适配器尚不支持实际完整提取 schema 的 `prefixItems` 和字符串长度约束；最小 schema 测试不证明完整兼容。本 GLM-only RC 明确延后该修复。
- CI 使用 Python 3.12，本轮本地使用 3.13.3，测试证据不能混写。已知 Starlette/httpx、AnyIO、SWIG 弃用警告如实保留，依赖升级另行维护。
- macOS 11.0 为构建最低版本元数据，不代表 macOS 11 实机验证。本轮开发主机 15.7.3；最终安装报告记录实际主机，最低版本若未实测须明确标注。
- 旧预发布合成报告可能含修复前的显示内容，不追溯改写已保存 payload/hash；不能宣称已全部重新脱敏。删除是逻辑清理，不承诺安全擦除 SQLite/WAL/备份。
- 工作流锁定工具链和依赖解析，但不声明安装包逐位可复现。
- 真实 Provider 验收必须由用户在应用内输入自己的 Key；缺少该验收证据时 PR 保持 Draft。
