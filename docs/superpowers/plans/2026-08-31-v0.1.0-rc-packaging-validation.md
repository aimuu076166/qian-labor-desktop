# v0.1.0-rc.1 Unsigned Packaging Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task by task.

**Goal:** Produce and verify unsigned macOS arm64 and Windows x64 release-candidate installers for `v0.1.0-rc.1`, with real built-sidecar smoke tests, packaged-application smoke tests, checksums, build manifests, and retained GitHub Actions artifacts.

**Architecture:** Keep the existing desktop product behavior unchanged. Add a shared verification harness around the existing loopback sidecar API, a narrowly gated packaged-app smoke mode that writes only non-sensitive evidence below the operating system temporary directory, platform bundle inspection, deterministic artifact staging, and manifest/checksum generation. Run the expensive packaging jobs only for release branches or manual dispatch, then combine both platform outputs in a third job.

**Tech Stack:** Python 3.12, pytest, Rust 1.98, Tauri 2, Node.js 22, pnpm 9.15.0, PyInstaller, GitHub Actions, macOS DMG/application bundles, Windows NSIS.

---

## Constraints and completion gates

- Preserve the existing `0.1.0` application/package versions. Express the candidate only through the external label `0.1.0-rc.1` in artifact names and manifests.
- Do not add product features, server infrastructure, production providers, real credentials, real user data, signing, notarization, a Git tag, or a GitHub Release.
- Keep all verification data synthetic. Preserve R01-R20, source trace, insufficient-data behavior, and human-review semantics.
- Never print sidecar tokens, secrets, database contents, or sensitive matching text in success or failure output.
- `signed` and `notarized` must remain `false`; macOS tool-generated ad-hoc Mach-O signatures are not a Developer ID signature.
- A packaged-app smoke result may be `PASS` only after the packaged main application starts its bundled sidecar, creates the temporary SQLite data directory, exits, and leaves no live sidecar PID.
- If either hosted runner cannot complete packaged-app smoke reliably, record `NOT_RUN`, keep the pull request in Draft, and explain the limitation without converting it to `PASS`.
- The branch is never merged as part of this plan.

**Files:**

### Step 1: Implement bundle inspection

`scripts/verify_rc_bundle.py` accepts `--platform macos|windows`, one or more `--payload` directories, `--source-config apps/desktop/src-tauri/tauri.conf.json`, and `--expected-commit`. It must verify:

- the checkout commit equals the expected commit;
- config version is `0.1.0` and identifier is `cn.qianlabor.desktop`;
- macOS `Info.plist`, main Mach-O, and sidecar Mach-O are arm64;
- Windows main PE and sidecar PE are AMD64 and the main executable version begins with `0.1.0`;
- exactly one main executable and one sidecar are present in each payload;
- no prohibited filename is present;
- no text or binary payload includes secret-like data, hosted-runner workspace prefixes, user-home build paths, or temporary-build prefixes.

Inspect executable headers directly with Python standard-library binary reads. On Windows, obtain the version resource through `ctypes`; do not add a binary-inspection dependency.

### Step 2: Implement deterministic staging

`scripts/stage_rc_artifacts.py` must require exactly one platform installer and payload. Produce only these ASCII names:

```text
qian-labor-desktop-0.1.0-rc.1-macos-arm64-unsigned.app.tar.gz
qian-labor-desktop-0.1.0-rc.1-macos-arm64-unsigned.dmg
qian-labor-desktop-0.1.0-rc.1-windows-x64-unsigned-nsis.exe
```

Preserve application permissions and symlinks in the macOS archive. Refuse overwrites, extra candidates, missing files, or symlink escapes.

### Step 3: Implement manifest generation and combination

`scripts/rc_manifest.py create-platform` computes sizes and SHA-256 values from disk and records:

```json
{
  "app_version": "0.1.0",
  "rc_label": "0.1.0-rc.1",
  "git_commit": "<40 lowercase hexadecimal characters>",
  "signed": false,
  "notarized": false,
  "real_provider_smoke": "NOT_RUN",
  "image_input": "NOT_RUN",
  "platform": "macos or windows",
  "architecture": "arm64 or x64",
  "artifact_name": "ASCII artifact filename",
  "artifact_size": 1,
  "sha256": "<64 lowercase hexadecimal characters>",
  "built_sidecar_smoke": "PASS",
  "packaged_app_smoke": "PASS or NOT_RUN",
  "toolchain": {
    "node": "captured version",
    "pnpm": "captured version",
    "python": "captured version",
    "rustc": "captured version"
  },
  "workflow": {
    "repository": "owner/repository",
    "run_id": "numeric string",
    "run_attempt": "numeric string"
  },
  "built_at": "UTC ISO-8601 timestamp"
}
```

The platform file may contain an `artifacts` array when one platform has two deliverables, but every array entry must contain all artifact-specific required fields. `combine` reopens every downloaded artifact, recomputes its size and hash, requires both platforms and one identical commit, rejects duplicate names, writes `BUILD-MANIFEST.json`, and writes sorted canonical `SHA256SUMS.txt`.

### Step 2: Implement `macos-arm64-rc`

On `macos-15`:

1. check out the exact event commit;
2. install pinned Node, pnpm, Python, and Rust toolchains;
3. run frozen dependency install and focused verifier tests;
4. run source-sidecar verification;
5. build the arm64 PyInstaller sidecar and run built-sidecar verification;
6. run frontend tests/build, Cargo tests/check, and release Tauri build with `--bundles app,dmg --no-sign --ci -- --locked`;
7. mount the DMG read-only into a fresh runner temporary directory;
8. inspect both the original `.app` and mounted DMG payload;
9. run packaged-app smoke against the mounted application executable;
10. detach the DMG even after a failed inspection;
11. stage the `.app.tar.gz` and `.dmg`, create platform evidence, and upload for 14 days.

### Step 3: Implement `windows-x64-rc`

On `windows-latest`:

1. perform the same source, test, built-sidecar, frontend, and Rust gates;
2. build with `--bundles nsis --no-sign --ci -- --locked`;
3. silently install the exact NSIS candidate below `RUNNER_TEMP` using `/S` and `/D=`;
4. inspect the installed payload and verify AMD64 binaries;
5. run packaged-app smoke against the installed application executable;
6. run the generated uninstaller silently and remove only the validated runner-temporary install directory;
7. stage the NSIS `.exe`, create platform evidence, and upload for 14 days.

### Step 4: Implement `rc-manifest`

Require both platform jobs to succeed. Download both named artifact sets, recompute all hashes with `scripts/rc_manifest.py combine`, and upload one final artifact containing the three installers/application archives plus `SHA256SUMS.txt` and `BUILD-MANIFEST.json`, retained for 14 days.
