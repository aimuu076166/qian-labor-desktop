# 企安用工 Desktop 真实可用版收口设计

**状态：** 用户已于 2026-08-31 批准执行

## 目标

在现有 Tauri 2 + React + Python sidecar + SQLite 架构上补齐真实可用闭环。保留现有 R01—R20、来源追溯、资料不足门禁、删除语义和本地优先边界，不重新设计产品，不迁入云端依赖。

最终用户路径：

```text
首次启动设置智谱 API Key
→ 测试连接
→ 导入企业材料
→ 本地解析与隐私处理
→ 智谱 GLM 提取结构化事实
→ 自动员工匹配
→ 必要时人工匹配
→ R01—R20 规则计算
→ Dashboard / 风险详情 / 员工台账 / 报告
```

## 收口范围

必须交付：

1. 智谱 GLM 单一真实 Provider 的普通用户设置入口；
2. macOS Keychain 安全持久化 API Key 和本地生成的隐私 pepper；
3. 连接测试及明确的真实/演示模式标识；
4. 正确的处理状态、文件错误和重试入口；
5. `matching_review` 人工匹配 API、界面和处理恢复；
6. 完整 Dashboard、风险详情和来源追溯；
7. 员工台账及员工详情；
8. 应用内报告及 macOS 打印/保存 PDF；
9. Apple Silicon macOS 安装包及端到端验收。

明确不做：

- 登录、企业账号、多租户、云同步、多人协作；
- Windows 安装包；
- 多 Provider 产品界面；
- 在线升级和备份迁移；
- Word 报告编辑器；
- 新增或改写劳动法规则；
- 视觉重构。

## 关键产品决策

### 首次启动不是登录

应用没有 Web 访问码或登录页。未配置有效智谱凭据时，首页显示首次设置，引导用户录入 Key、选择模型并执行不含材料的连接测试。设置完成后直接进入材料导入。

### 正式模式不静默使用 Fake

Fake Provider 只服务自动化测试和显式演示。普通用户流程没有有效真实 Provider 时必须阻止分析并显示可操作错误，不允许回退 Fake，也不允许把 Fake 结果标为真实分析。

### 人工匹配是分析门禁

`matching_review` 不是完成状态。存在待处理候选时只能进入人工匹配。用户完成所有候选决定后，sidecar 恢复规则计算；只有评估完成后才允许展示完成态 Dashboard。

### 报告收口为打印 PDF

报告使用 Dashboard、员工台账、风险发现和来源数据生成应用内只读报告。首版通过 macOS 系统打印功能保存 PDF，不引入 Word 模板或新的报告编辑器。

## 安全边界

- Key 和 pepper 仅由 Rust/Tauri 读取系统凭据存储；
- Key 不进入 React 状态、localStorage、HTML、SQLite、日志、截图、fixture、Git 或安装包；
- Rust 启动 sidecar 时仅向子进程会话注入秘密；
- sidecar HTTP 不提供读取 Key 的接口；
- Provider 只接收经过现有本地隐私边界处理的最小必要内容；
- 真实 Provider 测试只使用 synthetic 材料。

## 验收原则

只有以下闭环全部成立才可称为真实可用：

- 无 Key、错误 Key、连接失败和模型失败均有明确错误；
- 已知 synthetic 材料经真实 Provider 可产生员工、事实和风险；
- 人工匹配完成后能继续计算；
- R01—R20、来源追溯和资料不足语义保持不变；
- Dashboard、员工台账和报告口径一致；
- 重启持久化、删除清理和 sidecar 生命周期验证通过；
- 最终安装包对应提交精确可追溯并在 Apple Silicon Mac 上完成安装后验收。
