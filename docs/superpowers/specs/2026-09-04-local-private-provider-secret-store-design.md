# 本地私有 Provider 凭据存储设计

## 目标

移除企安用工 Desktop 对 macOS Keychain 的全部依赖，使无 Developer ID 签名的 RC 不再弹出 macOS 登录钥匙串密码框。用户仍只在应用设置页输入一次智谱 API Key，模型固定为 `glm-5.3-flash`，其余产品功能和交互不变。

## 存储边界

- API Key 和随机生成的 PII pepper 分别写入应用私有数据目录下的独立秘密文件。
- Unix/macOS 上秘密文件权限必须为 `0600`，仅当前用户可读写；写入采用同目录临时文件加原子重命名。
- 拒绝读取或覆盖符号链接、非普通文件和超出长度上限的内容。
- API Key 不进入 React 状态回显、SQLite、日志、测试 fixture、Git 或安装包。
- sidecar 启动时读取秘密并仅通过受控子进程环境传递；启动器仍先清除继承环境中的同名秘密。
- 旧 Keychain 项目不读取、不修改、不自动删除，因此新版不会触发 Keychain 授权框。

## 用户流程

1. 首次启动显示智谱连接设置页。
2. 用户输入智谱 API Key，点击“保存并测试连接”。
3. 应用直接保存并测试，不要求 Mac 密码。
4. 连接通过后进入材料导入页；后续启动沿用本地私有凭据。

设置页文案改为“API Key 仅保存在本机当前用户的应用私有目录”，不再宣称使用 Keychain。

## 错误处理

- 创建目录、权限设置、原子写入或读取失败时，只返回稳定错误码，不暴露路径或秘密。
- 本地凭据缺失时保持未配置状态，分析功能继续被门禁拦截。
- 原有 Provider 连接失败错误码保持不变。

## 验证

- Rust 单元测试先证明秘密文件写入、读取、`0600` 权限、符号链接拒绝和 sidecar 环境注入。
- 前端测试证明设置页不再出现 Keychain 文案。
- 运行完整前端、Python、Rust、敏感信息及公开历史检查。
- 最终 head 重新生成 Apple Silicon DMG，完成清单、哈希、只读挂载、bundle、普通启动及异常退出清理验收。
- PR #2 保持 Draft；只有用户用自己的 Key 完成 synthetic 真机分析后才转 Ready，不合并。

## 明确取舍

本方案避免 Keychain 授权和明文广泛暴露，但同一 macOS 用户权限下的恶意进程理论上仍可读取 `0600` 文件，静态保护弱于 Keychain。该取舍由用户明确选择，以换取当前无签名 RC 的可用性。
